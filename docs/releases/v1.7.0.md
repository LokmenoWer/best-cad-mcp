# v1.7.0 - Native MCP Python SDK 2.0

best-cad-mcp now runs natively on MCP Python SDK 2.x and the MCP 2026-07-28
protocol while continuing to serve legacy MCP clients through the SDK's
compatibility path.

## Highlights

- Replaced the removed `FastMCP` API with the native v2 `MCPServer`, `Context`,
  and `Image` APIs.
- Declared `mcp[cli]>=2.0.0,<3.0.0` and aligned the Windows/runtime dependency
  floors required by MCP 2.
- Added full MCP discovery metadata, including the best-cad-mcp version, title,
  description, and website.
- Migrated protocol-model access to MCP 2's snake_case Python attributes.
- Preserved single-threaded AutoCAD COM dispatch. MCP 2 normally moves
  synchronous handlers into worker threads; best-cad-mcp registers async
  event-loop facades so its shared AutoCAD COM controller remains on one
  serialized thread.
- Added a native MCP 2 in-process client test that negotiates the 2026-07-28
  protocol, discovers tools, calls a tool, and verifies its thread boundary.
- Added real stdio coverage for modern and legacy negotiation, resource reads,
  prompts, structured tool results, and mixed text/image tool content.
- Made `cad-mcp-doctor` reject incompatible MCP 1.x or future 3.x runtimes with
  an actionable `mcp_sdk_version` blocker.
- Expanded Release CI with an explicit MCP 2 runtime gate and a clean built-wheel
  smoke test.

## Verification scope

The hosted release gate runs the non-COM suite on Python 3.11, exercises modern
and legacy MCP over a real stdio subprocess, clean-installs the built wheel, and
checks both wheel and sdist metadata with Twine. Hosted CI cannot connect to
AutoCAD; live COM preflight and drawing operations remain a local release check
on a licensed Windows AutoCAD installation.

Local verification clean-installed the wheel on Python 3.11 with MCP 2.0.0,
connected to an active AutoCAD instance over real MCP 2026-07-28 stdio, passed
the live runtime preflight, and read the active document with
`get_document_info`. No drawing modification was performed.

Upgrade with:

```powershell
python -m pip install --upgrade "best-cad-mcp==1.7.0"
```

# v1.7.0 - 原生迁移至 MCP Python SDK 2.0

best-cad-mcp 现已原生运行在 MCP Python SDK 2.x 与 MCP 2026-07-28
协议上，同时继续通过 SDK 的兼容路径服务旧版 MCP 客户端。

## 主要变化

- 用 v2 原生的 `MCPServer`、`Context` 与 `Image` API 替换已移除的
  `FastMCP` API。
- 依赖范围改为 `mcp[cli]>=2.0.0,<3.0.0`，并同步提高 MCP 2 所需的
  Windows 与运行时依赖下限。
- MCP discovery 现在会报告 best-cad-mcp 的版本、标题、描述与项目网址。
- 协议模型属性访问已迁移为 MCP 2 的 snake_case Python 命名。
- 保持 AutoCAD COM 单线程派发。MCP 2 默认会把同步 handler 放到 worker
  thread；best-cad-mcp 改为注册异步事件循环 facade，使共享 AutoCAD COM
  控制器继续在单一串行线程上执行。
- 新增 MCP 2 原生客户端集成测试：协商 2026-07-28 协议、发现工具、调用
  工具，并验证线程边界。
- 新增真实 stdio 覆盖：modern/legacy 协商、资源读取、Prompt、结构化工具结果，
  以及文本与图像混合内容。
- `cad-mcp-doctor` 现在会拒绝不兼容的 MCP 1.x 或未来 3.x 运行时，并报告可操作的
  `mcp_sdk_version` 阻断项。
- Release CI 新增 MCP 2 运行时硬性校验与构建后 wheel 的干净安装烟测。

## 验证范围

Hosted Release 门禁会在 Python 3.11 上运行非 COM 测试，通过真实 stdio 子进程
验证 modern 与 legacy MCP，干净安装构建后的 wheel，并用 Twine 检查 wheel 与
sdist 元数据。Hosted CI 无法连接 AutoCAD；实时 COM 预检与图纸操作仍需在已授权的
Windows AutoCAD 本机环境完成。

本机验证已在 Python 3.11 与 MCP 2.0.0 的干净环境安装该 wheel，通过真实 MCP
2026-07-28 stdio 连接当前 AutoCAD，完成实时运行时预检，并用
`get_document_info` 读取活动文档；验证过程未修改图纸。

升级命令：

```powershell
python -m pip install --upgrade "best-cad-mcp==1.7.0"
```
